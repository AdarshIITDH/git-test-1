## PHASE 1 — Discover exact failure

Obtain the correct downstream kubeconfig from the existing authorized Rancher configuration.

Confirm the target is `agentic-ai` before making any changes.

Find the actual crashing Device Plugin pod, container, DaemonSet and namespace.

Run the necessary checks:

```bash
kubectl get nodes -o wide
kubectl get pods -A -o wide
kubectl get clusterpolicy -o yaml
kubectl get events -A --sort-by=.lastTimestamp
```

Inspect the failing component using its actual name:

```bash
kubectl -n <namespace> describe pod <device-plugin-pod>
kubectl -n <namespace> logs <device-plugin-pod> --all-containers --previous --tail=200
kubectl -n <namespace> logs <device-plugin-pod> --all-containers --tail=200
```

Also inspect:

- GPU Operator controller
- NVIDIA driver components
- NVIDIA Container Toolkit
- GPU Feature Discovery
- GPU Operator validator
- NVIDIA device-plugin configuration
- GPU Operator Helm chart and values
- NVIDIA runtime/CDI configuration
- Kubernetes node conditions and GPU labels

Do not guess the cause from CrashLoopBackOff alone.

## PHASE 2 — Diagnose host GPU and vGPU

Using authorized node access, run:

```bash
nvidia-smi
nvidia-smi -q
```

Verify:

1. NVIDIA GPU is visible on the SLES VM.
2. NVIDIA driver initializes correctly.
3. NVML library is accessible.
4. vGPU license is active and usable.
5. No GPU driver initialization errors.
6. NVIDIA Container Toolkit and RKE2 containerd configuration are compatible.
7. GPU Operator's driver-management settings match the actual host driver installation.
8. NVIDIA Device Plugin can discover the GPU.
9. Kubernetes allocatable `nvidia.com/gpu` resource is registered.
10. No conflicting NVIDIA Device Plugin installations exist.

Investigate these possible failure categories:

- NVML initialization failure.
- GPU driver unavailable or incompatible.
- Container runtime/CDI mismatch.
- Device Plugin configuration error.
- GPU discovery failure.
- Missing required libraries or mounts.
- vGPU licensing problem.
- GPU Operator version/runtime compatibility.
- Node resource pressure.

Identify the **exact root cause from logs and runtime evidence** before applying a fix.
